# Source-level audit — 2026-11-07

**Repository:** `Joka-kun/xiaomi-so-diffuser-ble` · **integration:** `so_diffuser_ble` · **scope:** latest `main` and PR for the next release. This is a source/CI review, **not** a new physical-device acceptance report.

- Direct source inspection: `client.py`, `protocol.py`, `coordinator.py`, `light.py`, `config_flow.py`, `provisioning.py`, `xiaomi_oauth.py`, `token_store.py`, entity modules and `manifest.json`.
- Real GitHub Actions results: Python unit tests, Hassfest and HACS validation; previously 122 tests and 64 subtests passed, HACS 10/10 on the pre-audit `main`. Recheck the final commit's runs rather than assuming those results remain valid.
- Synthetic, secret-free test inputs for commands, state validation, and OAuth. The original HCI capture and real GATT tokens are private and are not included here.
- Canonical Home Assistant [light entity](https://contributors.home-assistant.io/core/entities/light/) and [config-entry lifecycle](https://contributors.home-assistant.io/core/integrations/config-entries/) requirements. `ColorMode.ONOFF` during an active effect is explicitly supported despite `RGB` being the supported adjustment mode; no speculative change is needed.

## Reviewed boundaries (no speculative changes)

- **BLE:** fixed property allowlist, serialized writes, bounded transaction counters, authenticated responses and matching state read-back; artificial cases cover stale notifications and true timeouts. Physical timing, radio interference, FW-specific behavior and concurrent phone ownership are not established by CI.
- **OAuth:** one-time callback protected by unpredictable state, exact redirect and explicit cloud model selection; credentials are saved only after GATT authentication. Cloud availability and real user journeys remain physical/integration acceptance items.
- **Entity lifecycle:** observer removal on unload, bounded software palette loop and disconnect cancellation; historical `so_s5` → `so_diffuser_ble` transition needs actual HA registry and automation checks.
- **Publishing:** HACS 10/10 and Hassfest on the baseline do not constitute public catalog admission or model certification. `S5` is the only field-reported working model; other SO profiles are experimental.

## Physical S5 release gate

1. Back up HA and record domain, integration version and entity IDs before installing a new release; do not export secrets.
2. Pair/authenticate through Xiaomi OAuth, verify token file **presence and mode only**, and confirm exact device/model match.
3. Validate power OFF/ON, spray 3/middle/30 seconds, pause 3/middle/30 minutes, and zero-pause restoration with physical observation.
4. Validate RGB steady light, brightness, native gradient, and HA software Color Cycle/Sunset; switching light off must stop software color writes.
5. Force disconnect/reconnect, restart HA and test WAN-off BLE control. Check no duplicate config entries and no broken automations after any domain migration.
6. Re-run Python tests, Hassfest and HACS validation on the release commit; record the results as acceptance evidence. Do not mark non-S5 models verified without testing their actual firmware.

**Release policy:** Do not rewrite `v1.0.0`. A new release must have a new tag and manifest version and include the root MIT license. No real S5 test was performed by this audit.
